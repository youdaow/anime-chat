# animechat · 会甩表情包的二次元聊天 AI

本地跑的角色扮演聊天应用。三件事是它的核心：

1. **像那个角色**：人设 + 说话方式 + 语气示范，性格字段独立可调，不是把一段简介塞进 prompt 完事。
2. **真的会发表情包**：角色自己决定什么时候甩图，甩哪张由表情库的标签匹配决定；它没说出口的时候，服务端按这句话的情绪兜底补一张。
3. **接你自己的模型**：填三格 —— **Base URL + Key + 模型名**，官方平台、自建中转站、本机 Ollama 都是这一个形状，程序不预设你该用谁家的。什么都不填也能跑——内置 Mock 假模型，整条链路照常演示。

## 30 秒跑起来

```powershell
cd anime-chat
.\scripts\install.ps1      # 建 venv、装依赖、生成内置表情包和头像、自检
.\scripts\start.ps1        # 启动并自动开浏览器
```

浏览器打开 **http://127.0.0.1:8899**。首次进来是 Mock 模式（界面上有黄条提示），聊天、发表情、导角色卡全部可用。

想直接跑命令：

```powershell
.venv\Scriptsanimechat.exe run          # 启动
.venv\Scripts\animechat.exe doctor       # 环境 / 素材 / 模型服务 / 数据库自检
.venv\Scriptsanimechat.exe build-assets # 重新生成内置表情包与头像
.venv\Scriptsanimechat.exe add-sticker 傲娇.png --tags 傲娇,哼,别误会 --emotion tsundere
.venv\Scriptsanimechat.exe import-card 某角色.png
.venv\Scriptsanimechat.exe export-card xingye-liuli 星野琉璃.png
```

> 装不上 uv 的时候：
> `python -m venv .venv; .venv\Scripts\pip install -e ".[dev]"`

## 接模型：自带 Key，接口给你留着

设置 → 模型 最上面是**接入方式**下拉，它由后端那张注册表给（`GET /api/providers` ← `providers.py`）：
**主流平台的地址已经预置进去**（DeepSeek / 通义千问 / 智谱 GLM / Kimi / OpenAI 官方），选一家就自动把
Base URL 填好并锁成只读，你**只贴一个 Key** 就能用；最下面是**「自定义 / 中转站」**（自己填地址，走代理
或没列到的平台都用它）和**「内置 Mock」**（收掉地址和 Key 两格）。以后要加 Anthropic 原生 / Gemini /
本地 ollama：**在 `providers.py` 里添一条**（`family` 决定 `llm.py` 走哪套实现，`base_url` 填了就是预置
平台），前端一格都不用改 —— 这个口子是特意留出来的，将来给别人用时他们本来就是自带 Key。

### A. 直连平台 / 自建中转站（有 Key 就走这条）

界面右下角 **设置 → 模型**：接入方式挑一家平台（地址已预置）或选「自定义 / 中转站」自己填 **Base URL**，
再填 **API Key** 和 **模型名**，然后点 **测试连接**。下面这张表就是预置进去的那几家：

| 平台 | Base URL（已预置） | 模型名示例 |
| --- | --- | --- |
| DeepSeek | `https://api.deepseek.com/v1` | `deepseek-flash`（V4.1，带视觉）/ `deepseek-v4-pro`（更强） |
| 智谱 GLM | `https://open.bigmodel.cn/api/paas/v4` | `glm-5.2` |
| Kimi | `https://api.moonshot.cn/v1` | `kimi-k3` |
| 通义千问 | `https://dashscope.aliyuncs.com/compatible-mode/v1` | `qwen3.7-plus` / `qwen3.8-max` |
| OpenAI | `https://api.openai.com/v1` | `gpt-6-astra`（当前旗舰） |
| 本地 Ollama | `http://127.0.0.1:11434/v1` | `qwen3:8b` |

> 模型名只是**示例**，各家几乎月月出新、旧名随时退役（比如 `deepseek-chat` 已被官方标记退役、
> 路由到 V4.1-Flash）。别照抄——点「测试连接」拉一次对方当前的真实清单，从候选里选最准。

两个容易踩的点：

- **模型名得是对方真有的那个 id**：点「测试连接」拉一次清单，从候选里选，别凭印象写。留空会被当场拦下（提示「还没填模型名」），不再兜底成某个默认值去撞 404。
- **Base URL 要带对版本段**：多数平台是 `/v1`，智谱是 `/api/paas/v4`。写错路径会 404，而不是「连不上」。

`测试连接` 会真的发一句话（不是只 ping），成功后把该平台的模型清单刷进「模型」输入框的候选里，直接选就行。失败时错误气泡里给出对方返回的原文 + 一句能行动的建议。

### B. 自己搭的中转站 / 本机网关

地址填中转站给你的那个就行（OpenAI 兼容协议都算，`http://127.0.0.1:端口/v1` 也算），Key 填中转站认的那个，
模型名照它的 `/v1/models` 清单填。

**本机地址不再被特殊对待。** 以前程序看到 `127.0.0.1` 就认定「那是那台选路网关」，给出的建议整排都是错的
（让你去一个已经不存在的界面建 Token），而自建中转站恰恰常常就跑在 127.0.0.1 上。现在不管地址是谁家，
都走同一张提示表。

### 错误提示都得落到「该去修什么」

`llm.hint_for()` 把对方返回的错误码翻译成人话，并且把主机名写进句子里，一眼看得出是哪家在说话：

| 情况 | 界面上会告诉你 |
| --- | --- |
| 地址空着就点测试 | 「还没填 Base URL」，并说清去哪一格填 |
| 模型名空着 | 「还没填模型名」，让你点「测试连接」拉一次清单 |
| `invalid_api_key`（401/403） | 点名该主机：Key 有空格 / 过期 / Base URL 与 Key 不是同一家 |
| `model_not_found`（404） | 点名该主机：没有这个 id，去下拉里选准确的 |
| `no_route_available` / `all_providers_failed` / `free_router_exhausted` | 中转站自己汇报的选路失败：展开「路由 N 次」看每次打了谁 |
| `rate_limit_exceeded`（429） | 限流或额度用尽：稍等再发、换个模型，或去平台充值 |
| `context_length_exceeded` | 上下文太长：调小「上下文字符预算」，或让角色先总结记忆 |
| `connection` | 连不上：查网络和代理，以及是不是漏了 `https://` 前缀、`/v1` 结尾 |
| `empty_completion` | 上游回了 200 但没正文。按现场分三种说法：思考吃光了 token / 只想不说 / 什么都没回（见下一节） |
| 上游 5xx 且响应体为空 | 写清楚「HTTP 503，响应体是空的」，不会只甩一个裸错误码 |

认不出的错误码**不给建议**：宁可少说一句，也不编一个动作出来让人白跑。

中转站要是会选路并回一个 `hub.attempts`，每条 AI 回复下面就多一个 **路由 N 次** 按钮，列出这次试了哪些
上游、各自耗时和状态码——慢在哪、换了谁，不用猜。没这个字段就是普通直连，一切照常。

### reasoning 模型（qwen3 / R1 这类）会有两个错觉

这类模型先打草稿、再说话。界面上草稿不会消失也不会挡住正文：气泡上方多一个虚线折叠块
「思考过程（N 字）」，思考时自动展开、正文一开始就自动收起，点开就能看到模型在想什么。
（它同时存在那条回复的 meta 里，刷新页面还在。）

- **「卡住了」**：其实在思考。折叠块字数在涨就是正常的；嫌慢就换非 reasoning 的模型 id。
- **「回了个空的」**：思考过程也计入设置里的「最大回复 token」。默认 800 对这类模型偏小，
  可能想完就被截断、正文一个字都没有。这种情况现在会明确报错并让你把这个值调到 2000 以上，
  而不是留一个空气泡让你猜。

代码上的对应：`llm._events_from_object()` 把 `delta.reasoning_content` 单独编成 `reasoning` 事件，
`server.py` 的 `stream()` 累积思考并在收尾时判断「有思考没正文」，形状夹具见 `tests/test_reasoning.py`。

## 表情包是怎么发出来的

角色不是随机甩图。一次回复里有两层决策：

- **模型主动**：人设要求它在情绪落点输出 `[sticker:傲娇]`，服务端把这个标记从文字里摘掉，换成真图推给前端。
- **服务端兜底**：模型没标任何记号时，按这句话检测到的情绪（`light` 只在明显情绪时补）挑一张合适的图。

选图顺序：精确 id → 归一化标签命中 → 情绪匹配（角色偏好的标签加权）→ 收藏 → 稳定随机。匹配做了**归一化**：全角半角、大小写、标点空格都会先抹平，所以模型写 `tsun`、`傲娇`、`［表情：傲娇］` 都能命中同一张。

标记协议、流式切分与情绪 key 的完整说明在 `docs/PROTOCOL.md`。

### 三种加图方式

1. **内置 30 张**：程序画的 Q 版表情包（`animechat build-assets` 生成，源码 `src/animechat/chibi.py`），带 11 种情绪的标签，开箱就能聊。不想要就在表情包库或选择器里对它点删除——内置图删除＝**隐藏**（素材留在程序包里，跑 `animechat unhide-stickers` 全部放回来）。
2. **往文件夹丢图**：把 png/gif/webp 扔进 `data/stickers/`，界面立刻出现，不用重启。文件名用 `+` 分隔就是标签：`傲娇+哼+别误会.png` → 标签 傲娇 / 哼 / 别误会。（聊天窗口里那个「上传一张图当表情」的按钮已去掉，输入框只留选表情；要加图就往这个文件夹丢，或用下面的联网搜图入库。）
3. **联网搜图**：表情面板 →「联网搜索」，回车搜。默认 `provider=auto` 走**免 Key 的 Bing 图片**（实测这台机器上 DuckDuckGo 常被风控），设置里可换源。Bing 结果里带水印的素材站会被降权、透明底的 emoji 站 / GIF 站优先。点 **＋** 会**下载到本地**并入库——只存 URL 的外链图迟早 404，所以一律落地保存并记出处（`data/stickers_meta.json`），**并且当场给它起一个能用的定义**（见下）。要 Key 的 Tenor / Giphy 已从界面移除：填了也用不上，别再为它们去注册。
4. **一次抓一批**：`python scripts/fetch_stickers.py`。它按 11 种情绪各搜几条（哭、抱抱、傲娇、炸毛、震惊、困、思考……），逐条走上面的搜索 + 导入接口，抓到就是真·二次元动图。中文标签是角色挑图的依据，所以每张都带了情绪词。同一张图按内容 sha1 去重；因为每次搜索结果本身不同，再跑一次是"再补一批"，不是重导。

选图时**联网 / 自己丢进来的图优先于内置手绘那批**（内置退回兜底，见 `stickers.py` 的 origin 加分），所以角色现在甩出去的基本都是从网上抓的图。内置那批留着是为了完全离线时也有表情可用。

### 每张图都得有「定义」，不然角色不会发它

角色挑表情有两条路：模型自己写 `[sticker:傲娇]`（按标签搜），或者它没写、服务端按这句话的情绪兜底补一张（按情绪挑）。两条路都吃**定义** = `label` + `tags` + `emotion`。

远程站的文件名多半是一串 CDN 哈希（`9lddQjsw k5ltZcT3cSs.jpg`、`b284e22577144f5daa67.png`）。以前直接把它当名字入库、把搜索词当唯一标签、情绪判不出来就记 `neutral`——于是提示词里那一项是一串乱码（模型根本不会写它），按情绪兜底又永远绕开这张：**图加进去了，角色一次都没发过**。

现在入库时现场补一份定义（`stickerdef.py`）：

- 从搜索词 + 结果标题里剥掉站点名和「表情包 / 高清图 / 素材 / gif」这类废话，取第一个中文词当名字；全是英文就用情绪中文名（搜 `tsundere gif` → 名字「傲娇」，英文原词留在标签里）；
- 情绪由**标签别名层**认（`emotion.ALIASES`：杂鱼 / 嘴硬 / 傲骄 / tsundere → 傲娇）。它和判断回复情绪的 `emotion.LEXICON` 是两套——前者认的是标签里的词，后者认的是句子里的情绪词，拿后者认标签会全部判成 `neutral`；
- 认不出情绪就老实留 `neutral`，绝不硬猜成「开心」。

库里已有的坏定义（老版本加的那批）在扫库时补一次，记 `defined=auto`，补过就不再反复改；你在「管理表情」里改过名字 / 标签 / 情绪的记 `defined=user`，自动补定义从此不碰它。发给模型的词表也每张都带情绪名：`杂鱼/傲娇/傲骄/嘴硬(傲娇)`；定义完全相同的（一次搜「杂鱼」能加进来十几张）在词表里只列一条，省 token 也不误导模型。

界面上「管理表情」可以改标签、改情绪、收藏、删除（内置图删除＝隐藏，见上）。每张图的格子上还有「预览」按钮，发之前先放大看一眼。内置图的自定义标签存在 `data/stickers_meta.json`，不会去改包内素材。

### 跟别人分享整套表情库（GitHub）

把你的表情库变成一个公开素材包，别人（和另一台电脑上的你）填仓库名就能整套拉走。

- **拉取**：设置 → GitHub 表情仓库 → 填 `用户名/仓库名` → 预览仓库 / 拉取到本地。公开仓库不需要任何 Key；
  同图按内容自动合并标签，重复拉取不会越同步越多。
- **发布**：双击根目录的 **`onekey-push.bat`**。它把 `data/stickers` 摊平成
  `stickers/stickers.json` + 图片，提交并推送到你填的那个仓库，**整库只产生一个提交**。

发布走的是 git（复用你电脑上的 GitHub 登录态），所以**不用申请 Token**；只有想在网页界面里点按钮发布
才需要一个勾了 `Contents: Read and write` 的 Token。仓库里那个目录的结构是纯文本清单 + 图片，
你也可以完全手动维护它。

> `pack-export/` 是一键脚本生成的工作副本（含 `.git`），不用手动改；删了它会重新生成。

## 角色与角色卡

内置 5 个性格分明的角色：傲娇大小姐、温柔学姐、毒舌 AI、元气后辈、中二魔法师。各自的「用图频率」不一样——毒舌那个刻意设成纯文字，正好用来对比效果。

- **自定义角色**：左侧「＋新建」，字段是拆开的：性格 / 说话方式 / 语气示范 / 口头禅 / 喜欢讨厌 / 底线。**「说话方式」和「语气示范」对像不像的影响最大**，比写一千字背景设定有用。
- **AI 生成**：左侧「AI 生成」，一行「角色名 + 出自哪部作品」就出整张卡（人设 / 说话方式 / 口头禅 / 语气示范 / 外观）并直接入库，同名一律不覆盖。**头像优先联网找立绘**（和表情包共用那条搜图 + SSRF 防护链路），下载后居中裁成正方形、缩到 256 存进本机（想自己决定留哪块，生成完点「微调位置」重框一次），之后断网也照样显示；搜不到（离线、原站防盗链、图太小）就退回程序画的 Q 版 —— 一次生成不该因为头像没着落就整单作废。做完的提示会写清每张头像是「联网立绘」还是「Q 版」。
- **头像随时能换**：点角色头像进编辑器 →「联网找头像」列一批候选让你挑（同名角色和同人图太多，自动取第一张经常张冠李戴，所以点哪张才用哪张）。**点完立刻弹一个取景框**：找回来的图大多不是正方形，服务端只会居中裁，横长条的立绘常常一刀切掉头顶 —— 于是让你拖着图片把想留的部分挪进方框，滚轮或下面的滑块放大，方框里就是最后的头像。旁边「重画 Q 版」按外观参数程序画一张，「上传头像」用你自己的图。不想沾别人的图，就到设置里关掉「AI 生成角色时联网找头像」，那样一律只画 Q 版。
- **框错了随时重来**：编辑器里的「微调位置」对着上次下载的那张原图重新框一次，**只在本机重裁、不再联网**（原站把图撤了也照样能调）。代价是每个找过头像的角色会留一张 `<id>-src.png`（长边压到 1024，约 1MB），换一张就覆盖，不会攒一堆。「上传头像」「重画 Q 版」会清掉这张暂存并把「微调位置」置灰 —— 那时以你的图为准，再点微调就把上传的那张换回网图了。
- **导入**：支持 SillyTavern / Text-generation-webui 的 **Character Card v2 JSON**，也支持把卡内嵌在图片里的 **PNG 角色卡**（`data[`chara`]` 那种）。导入时 `mes_example` 会被解析成语气示范。
- **导出**：JSON 卡，或把卡写进头像的 PNG 卡（字段按 v2 规范放，本应用特有的 `sticker_prefs / sticker_style` 放在 `data.extensions.animechat` 下，别的软件会直接忽略，不会丢主线数据）。
- 内置角色改坏了：角色菜单 → **恢复出厂**。删除内置角色只是隐藏，同样能恢复。

## 在手机飞书里跟这些角色聊

一个独立的命令行进程（`animechat feishu`）挂在飞书那边收消息，收到就调用**本机**的 `/api/chat`，拿到回复再发回飞书。所以角色、表情包、总结记忆、提示词那些逻辑一行都没重写——网页和飞书看到的是同一个大脑，聊过的记录也落在同一个库里，回到网页照样能翻、能接着聊。

**为什么是单独一个进程，而不是网页里点个按钮**：它得一直连着飞书，是个阻塞的常驻循环。塞进浏览器就成了关不掉、也看不见日志的黑盒，出错时人完全没有抓手。

**为什么要装个包**：`pip install -e ".[feishu]"`（或 `uv pip install lark-oapi`）。网页端不装也照常跑，所以它没进主依赖——飞书 SDK 自己会拖一串东西，还会把 `websockets` 钉到 16 以下。

### 开通（八步，都在 open.feishu.cn/app）

1. 用飞书账号建一个**企业自建应用**。没有企业就先建一个，收事件这一步不要求企业认证。
2. 左侧「添加应用能力」→ 加**机器人**。
3. 「权限管理」搜 `im:message`，开通这三条：`im:message`（收发单聊与群消息）、`im:message.p2p_msg:readonly`（读用户发给机器人的单聊）、群聊再加 `im:message.group_at_msg:readonly`。**再单独搜 `im:resource` 开通「获取与上传图片或文件资源」** —— 上传图片走的是 `im/v1/images`，和发消息是两套权限。漏了它的表现特别迷惑：文字照发、表情包一张都没有，而且不报错。桥接窗口里会打一行「表情 xxx 上传失败：多半是没开 im:resource 权限」，对着上面那条补权限 → 重新发布版本 → 重启桥接就好。
4. 「事件与回调」→ 事件配置 → 订阅方式选**使用长连接接收事件** → 添加事件 `im.message.receive_v1`。
5. 「凭证与基础信息」里的 App ID / App Secret 抄到网页 **设置 → 飞书**，保存。
6. `animechat feishu --check`，照着 FAIL 那几行补齐。
7. `animechat feishu` 把窗口开着（**这个窗口一关，飞书立刻就不回话了**）。
8. 应用详情页「版本管理与发布」→ 创建版本 → 提交，然后手机飞书搜应用名点开就能聊。

设置里那一段还留着一份同样的清单，点开就能对着做。App Secret 只存本机 `data/settings.json`，接口回显一律掩码。

### 主动发言（沉默后触发）

开启后，在飞书私聊里如果你超过一段时间没说话，角色会自己找你聊天：

- 只对私聊生效（群聊不主动，避免打扰其他人）
- 必须真聊过才主动（不会骚扰刚绑定却没说过话的会话）
- 每个会话独立计数，跨天自动清零
- 主动开口时，系统会告诉角色「是你主动找ta」，避免写「在吗」「你怎么不理我」这类压迫感开头

在飞书里用 `/主动 on|off` 可以单独控制某个会话的主动开关，`/状态` 查看当前配置。

### 在飞书里能发什么

| 你发的 | 效果 |
| --- | --- |
| 普通一句话 | 当前绑定的角色回你 |
| `/角色` | 发一张带**下拉菜单**的卡片，点一下就换人（也可 `/角色 名字` 直接打名字） |
| `/角色 亚丝娜` | 这个会话换成她（**另起一条会话**，不然两个角色混在一段历史里会串戏） |
| `/表情 off` | 这个会话只回文字，不发图片（`on` 打开） |
| `/主动 on|off` | 沉默后角色主动找你（仅私聊，默认关，可在网页设置全局开关） |
| `/清空` | 忘掉这个会话里的历史 |
| `/状态` | 当前角色 / 会话 / 有没有带图 / 主动发言开关（含下次大约几点找你） |
| `/帮助` | 命令清单 |

> `/角色` 那张下拉卡片要在飞书后台「事件与回调」里**再加一条回调 `card.action.trigger`**（订阅方式同样选「使用长连接」），加完重新发布版本才生效。不加也不影响聊天：文字版 `/角色 名字` 照常换人，只是点不了下拉。跑 `animechat feishu --check` 也会提示这一步。

> **注意**：飞书卡片在 p2p 私聊中无法固定在输入框上方（只有群聊支持 Pin）。每次点完下拉换人，系统会自动发送一张更新后的卡片到当前会话，你可以随时切换角色。如果需要更便捷的切换，可以使用 `/角色 名字` 直接指定角色。

命令名前面加不加半角斜杠都认，中文别名（`/换角色`、`/帮助`）也认。群聊里**必须 @ 机器人**才回——飞书会把 @ 了别人的消息也推过来，不拦就等于在群里插嘴。

### 几个不写清楚一定会踩的点

- **长连接不填 Encrypt Key 和 Verification Token**。飞书只在建连时鉴权，推过来的事件是明文；填了反而让 SDK 去验一个不存在的签名，每条消息都被丢掉，症状是「已读不回」，极难查。这条被 `test_long_connection_mode_passes_empty_encrypt_and_token` 钉住了。
- **处理一条消息要在 3 秒内返回**，超了飞书就重推。所以收到事件先扔进工作线程，同时按 `event_id` + `message_id` 去重；模型跑十几秒是常事，都在后面那条线上。
- **回复超 1000 字会切成多条**，优先在段落、句子边界切，实在没有就硬切。第一条挂在你的消息下面（reply），后面几条另起（create）。图片先传到 `im/v1/images` 换 `image_key` 再发，所以表情包在飞书里是真图，不是文字。
- **网页端没开着**时，飞书那边会收到一句「连不上本机的 animechat……先跑 `animechat run`」——不是石沉大海。跨机部署就在设置里填「桥接回调地址」。
- **发图 / 语音 / 文件**目前明确回一句「看不了」，而不是已读不回。已读不回是最糟的体验。
- `/me 摸摸头` 这类**不会**被当命令拦掉，那是角色扮演动作，原样交给模型。

`animechat feishu --bindings` 看哪些会话绑了谁，`--unbind <角色id>` 解一个，`--unbind all` 全解。`doctor` 里也有一行飞书自检，**没配也不报错**，只是提一句。

> 个人免费版能不能一直这么用，官方文档没写死（「免审」「免费」是企业版口径）。这套走的是长连接 + 自建应用，不需要公网、域名、备案，测试和自用的是够的；要长期挂在手机上，建议自己先拿一个小号试一天。

## 其它功能



- 会话：多会话、置顶、重命名、删除；每条 AI 回复可 **重新生成**、**删到这儿**（回滚重来）。
- **自己这一侧也是有脸的**：设置 → 我是谁 → 我的头像。可以本机上传，也可以「联网找」一张（复用角色头像那套：候选点哪张用哪张，点完弹取景框让你拖位置，原图留在本机，以后随时「微调位置」重裁）。没头像就退回名字第一个字。配合格子里的「我的名字」「关于我的补充设定」（后者会进系统提示词，角色因此知道你是谁）。
- **总结记忆**：把长对话压成角色视角的摘要，之后的请求只带摘要 + 最近几条，长聊不爆上下文。
- **上下文**：一个只读弹窗，展示这次真的发给模型的原文和字数——调人设不用猜。
- 界面照主流 IM 抄的作业：**浅色 = 微信**（灰底 + 白/绿气泡 + 绿色发送按钮），**深色 = Telegram Desktop**（#17212B 侧栏、#0E1621 聊天底、蓝色自己的气泡、蓝色发送）。侧栏底部 ☾ 一键切换，选择记在 localStorage。气泡带朝外的小尾巴；表情包按 Telegram 的做法直接发图、不套气泡。`style.css` 顶部注释写清了两套变量对应哪个软件。
- **未读红点**：角色回了话而你还没看到，侧栏就挂一个**红色**小气泡显示条数（超过 99 收成 `99+`）。只数角色的回复——你自己发出去的那条不该给自己点红点；会话打开即清水位，标签页切到后台时到货的那句才算未读。水位线 `last_read_id` 存在 SQLite 里，所以刷新、重开都在；老库升级时一次性回填成「全部已读」，不会一打开满屏红点。
- 移动端宽度自适应：平板 / 手机把侧栏收成 74px 头像窄栏时，红点改挂在**头像右上角**（会话那一行则居中显示），不至于跟着灰色的会话数一起被藏掉；≤620px 另有手机一档（更大的气泡与点按区域、让出刘海/手势条安全区、`100dvh` 适配伸缩的地址栏）。Markdown 内联渲染（`**粗体**` / ``代码``）、点图放大。

## 常见问题

**黄条一直说 Mock 模式？** 三种来路：接入方式选了「内置 Mock」、`llm_api_key` 空着、或模型名写着 `mock`。想用真模型就在设置 → 模型 的「接入方式」里挑一家平台（地址已预置，只填 Key + 模型名），或选「自定义 / 中转站」自己填 Base URL，保存后黄条自己消失。
**测试连接报 401？** 地址通、Key 不通：多半是这家的 Key 过期 / 复制时带了空格，或者 Base URL 和 Key 根本不是同一家。建议就在错误气泡里，不用去猜。
**内置表情包是空的？** 跑 `animechat build-assets`（install 脚本会自动跑）。生成失败会打印原因，通常是缺 Pillow。想要真·二次元图，跑 `python scripts/fetch_stickers.py` 联网抓一批。

**缩略图被裁成一条横带？** 已修：Chrome 给 grid 的 auto 行算内在尺寸时，带 `aspect-ratio` 的图贡献算 0，整行塌成一行字幕高。现在 `picker-grid`/`lib-grid` 显式 `grid-auto-rows: max-content`（测试锁住了这个坑）。老页面若还有，强刷一次（Ctrl+Shift+R）。
**联网搜索没结果？** 默认源是 Bing（免 Key）；它也可能改版，这时会如实报错而不是给你空列表。设置里换个源（Bing / DuckDuckGo / 自动）。搜到的图一律下载到本地才入库。
**联网加进来的表情，角色一次都没发过？** 八成是这张没「定义」：老版本会把远程站的哈希文件名当名字存进库（`9lddQjsw k5ltZcT3cSs.jpg` 这种），情绪也判不出来，等于加了个哑巴。现在扫库时会自动补上（打开界面就已经是补过的），也可以自己修：表情包库 →「管理表情」→ 改标签 / 改情绪，手动改过的以后不会再被自动改。判据是名字和标签里的词，所以标签写成「傲娇 / 杂鱼 / 嘴硬」这种**情绪词**最有用；只写「好看」「收藏」没人挑得中它。
**AI 生成的角色还是那张 Q 版圆脸，没拿到立绘？** 找头像和找表情是两套排序（站徽、小缩略图往后甩，而且不去动图库问）。退回 Q 版一般是这几种：当时没网、原站防盗链下不动、或搜到的图短边不到 140px（裁出来糊成一片，不如不用）。想自己挑：点角色头像进编辑器 →「联网找头像」，候选里点一张 —— 格子上写「预览被挡」也不要紧，那只是浏览器外链缩略图被挡，下载是服务端做的，点了照样能用。介意用别人的图就在设置里关掉「AI 生成角色时联网找头像」，那样一律只画 Q 版。挑中了却被切掉半张脸：候选点下去之后那个取景框就是给你挪位置的，当时没调也不要紧，进编辑器点「微调位置」随时重来（本机重裁，不会再下一次图）。
**换了端口打不开？** 只改过端口没改绑定：这个界面没有鉴权，请保持 `127.0.0.1`，别暴露到公网。
**左边角色列表整个不见了、点哪都没反应？** 布局被撑破：某层缺 `min-height:0`，会话一长 `.main` 就比视口高，`body{overflow:hidden}` 被输入框的 focus() 滚到底，侧栏整块滚出屏幕而且**滚不回来**（overflow:hidden 时滚轮不起作用）。已修，并加了防回归测试 `test_app_uses_inner_scroll_not_page_scroll`。自检：F12 控制台执行 `document.querySelector('.char-list').getBoundingClientRect().top`，负数就是又被撑破了，正常约 60~120。
**窗口窄于 900px 只剩一列小圆点？** 侧栏收成 74px 窄栏时角色名现在显示在头像下方，底部「设置 / 表情包库 / 关于」变成图标（不再整排隐藏，鼠标悬停有说明），点左上 `«` 可撑回 302px。未读红点在这档挂到头像右上角，不会因为文字被藏就看不见。
**红点消不掉？** 那个会话里确实还有没打开过的角色回复：点开它（标签页得在前台）才会把水位线推过去。手机 / 平板上如果只看到角色头像上的红点，点那个角色进不去具体会话时，展开侧栏（`«`）点会话那一行。
**给 A 发了消息，切去看 B，B 名字底下也写着「正在输入中」？** 已修，同一个根因还有第二个更糟的症状：A 的回复会流着流着画到 B 的窗口里。原因是这两样东西都只记「有没有人在等 / 屏幕上那个消息流」，不记「等的是哪个会话」。现在等待状态存的是会话 id（`typingConv`），流式气泡也绑定了自己的会话，切走就只攒内容不画屏，切回来还在等就重新提示。防回归：`test_typing_hint_belongs_to_the_conversation_that_is_waiting` 和 `test_inflight_stream_cannot_render_into_another_conversation`。
**想换数据目录（挪盘）？** 设 `ANIMECHAT_DATA_DIR=D:/animechat-data` 再启动，旧数据手动拷过去即可。

## 安全说明

- 聊天数据、角色卡、表情包全在本机 `data/` 目录，除了你配置的模型端点和搜图服务，不发往任何地方。
- 只监听 127.0.0.1；界面本身无鉴权，不要反向代理到公网。
- 联网搜图会拒绝内网/回环地址，重定向手动跟踪且最多 3 跳，单图上限 8MB，按魔数判定类型。
- 导入的角色卡内容会被当作**数据**注入提示词，不是可信指令：安全底线写死在系统提示词里，不受角色卡影响。
- 涉及自伤等危机话题时，提示词里有硬规则引导求助（热线 12356）。这是聊天玩具，不能替代真实援助。
